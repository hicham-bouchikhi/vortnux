# Implementation status

Updated 2026-10-11. The plans describe the full intended product; the current code implements the first Linux/Cyberpunk slice.

Vortnux is licensed under the [MIT License](../LICENSE). AppStream and Arch metadata declare MIT; portable, AppImage and Arch deliverables include the license text. Third-party dependencies retain their own licenses.

The native shell, ownership/deployment core, searchable Nexus mod/collection catalog, explicit Nexus REST v1/GraphQL adapter, generated v3 transport client (114 DTOs/38 methods), collection preflight/batch path, clickable activity navigation, release verifier/updater, packaging scripts and GitHub workflow are implemented. They are organized into Core, Desktop and Tests rather than the larger final project split proposed in the plan.

No compiler/linker/AOT warning suppression was introduced. Native publish and offline payload smoke tests have run locally. Fixture tests include real 7z archive creation/extraction, but use fake game executables and synthetic mod content. They do not constitute a live Nexus or game-compatibility certification.

AppImage and Arch package artifacts are built locally. The rebuilt AppImage and executable extracted from the rebuilt Arch package pass the native smoke test, and all 97 automated tests pass with warnings as errors. Their checksums are recorded in `dist/SHA256SUMS`; the current test report is `artifacts/test-results/card-grid-tests.trx`. A clean Arch install/remove is defined in CI; it has not been performed against the user's host system. Hosted CI and signed release publication need a real repository and publisher configuration. The local AppImage is a development build with no enabled publisher trust.

Browse result cards now include Install. Mod installation selects an exact file, downloads and stages it, then deploys through Install reviewed files. Collection installation resolves the published revision and inspects its manifest before downloading and reviewing the batch. Missing game setup routes to Games; free accounts retain authorized browser downloads, and automatic collection downloading is disabled without Premium. Headless tests exercise both complete installation flows through simulated Nexus responses, destination review, deployment, activity targeting and removal.

Browse opens after account connection and provides Mods/Collections tabs, name search, four sorts, 24-item pages, cancellation, stale-request rejection, a bounded session cache and result-to-download navigation. Mod thumbnails and collection cover images load asynchronously on cards and the selected-item view. Image requests use approved CDN hosts without credentials or automatic redirects, enforce byte/dimension limits, and use a bounded memory cache; visible bitmaps are disposed on navigation/closure. Installed mods filter by name and enabled/disabled status; collections filter by identifier or member name. Both public catalog queries and their name-search/download-sort variants were checked successfully against the live Nexus endpoint without credentials. Image fields and actual mod/collection CDN downloads also returned successfully. Evidence is in `artifacts/test-results/catalog-live-check.json`; headless fixture screenshots are `artifacts/screenshots/browse.png` and `artifacts/screenshots/browse-images.png`. Real-account download and game checks remain pending. Richer detail pages, installed-file badges and retained catalog scroll position remain follow-up work.

The headless GUI tests render the real controls and exercise navigation. A native desktop launch was attempted with isolated temporary state but failed with `XOpenDisplay failed` in this environment. That desktop check remains pending; CI defines an Xvfb gate. The release-shaped AppStream metadata was validated successfully using a fixture repository URL. Local unpublished packaging explicitly defers catalogue validation until a real homepage exists; compiler/linker/AOT warnings remain fatal.

Remaining full-product work includes profiles, discovery, persistent preferences, richer download management/resume, inter-instance nxm forwarding, arbitrary supported collection rules/installers, REDmod, RAR, further games, live account/collection/game verification, desktop notification action smoke checks and hosted release acceptance.

The implementation is reviewable and usable for supported file deployment. It is not the completion of every milestone in the longer plan.

The accepted [credential-storage ADR](adr/0001-nexus-api-key-storage.md) and [setup/recovery guide](credentials.md) document the current behavior. Nexus keys persist only through Linux Secret Service (`secret-tool`). No new local key file is written. Existing local keys migrate on startup: store and exact read-back verification must succeed before deletion; failed migration retains the legacy file and blocks the connection with unlock/retry instructions. Retry saved connection also recovers from temporary validation failures without retyping. Startup validates the saved key before reconnecting and preserves incoming download links. Forget removes the saved credential; Disconnect retains it. Tests cover restart, locked keyring retry, rejected keys, no plaintext writes, successful/failed migration, mismatched verification, removal, symlink/size rejection and secret-tool stdin transport using fixtures. The real desktop keyring could not be checked inside the sandbox; migration of the user's key happens on the next app launch.

Browse, installed mods and installed collections now use wrapping card grids. The tests verify multiple rows/columns and narrow-window reflow. README screenshots render the real GUI with a demo account; the mod screenshot uses a public catalog snapshot and collection data is a fixture. See [mod cards](screenshots/mods-cards.png) and [collection cards](screenshots/collections-cards.png). The project repository is https://github.com/hicham-bouchikhi/vortnux. Source and screenshots are published; CI is provided as `.github/ci-template.yml` until GitHub workflow permission is authorized. Hosted CI has not run.
